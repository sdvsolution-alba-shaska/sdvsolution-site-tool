How requirements work

Check the wiring against the I/O list

Import the communication matrix and the wiring drawings. The platform traces every wire and compares it, pin by pin, with what each ECU says it provides.

  • CAN, LIN, Ethernet and FlexRay from DBC, LDF and ARXML
  • Wiring drawings read from PDF, net by net
  • Wrong pins, unwired outputs and missing signals listed for you
How the cross-check works

Hand each supplier a complete ECU specification

A specification for every ECU, built from its own buses, connectors and safety level, so the supplier gets requirements that match the vehicle it goes into.

  • Hardware, software, diagnostics, update, cybersecurity and verification
  • Connector pin-outs and I/O lists per ECU
  • Every requirement with an ID and a verification method
What an ECU specification holds

Generate the software, feature by feature

Describe a feature as a behavior model. The software factory writes its C code and unit tests, then integrates the features deployed on each ECU into that ECU's software.

  • C code and unit tests per feature
  • ECU integration: signal routing, schedule, integration test
  • The complete vehicle as one package, ECU by ECU
How the software factory works

Know which ECUs are ready for the release

Every ECU delivers against a common vehicle release. Track each deliverable with its evidence and sign off ECU by ECU.

  • Deliverables and evidence per ECU
  • Sign-off per ECU and per release
  • Safety, cybersecurity and review status on one dashboard
